# Autonomous Decision Log

## Recovery points

- `recovery/apk-oracle` — original binary/oracle preservation point.

## Critical enhancement decisions

1. **Do not fabricate Android source parity.** R8-obfuscated DEX is retained as oracle rather than decompiled into guessed source semantics.
2. **Separate observation from inference.** Map records carry `Observed`, `Inferred`, or `Predicted` state so estimates cannot masquerade as measurements.
3. **Prefer coarse proximity over fake precision.** Exact RSSI ranging is represented only as a calibrated estimate; coarse bands remain usable without calibration.
4. **Reject randomized MAC as stable identity evidence.** The U/L bit is interpreted conservatively and supplemental evidence is modeled separately.
5. **Enforce monotonic observation time.** A track cannot silently accept backwards timestamps.
6. **Represent GNSS accuracy explicitly.** Positioned observations retain horizontal uncertainty and confidence.
7. **Use a conservative weighted region estimate.** The implementation estimates strongest observed region rather than claiming transmitter multilateration parity.
8. **Mechanize parity status.** Observed ABI, oracle-retained implementation and source-reconstructed behavior are distinct registry states.
9. **Preserve zero-dependency Rust core.** No external crate was introduced solely for convenience, keeping the workspace deterministic and audit-light.
10. **Never report unavailable Cargo/Android gates as green.** Package integrity is verified locally; compile/runtime gates remain explicit blocked items.

## Autonomous advancement decisions (2026-08-28)

11. **Execute formerly blocked gates the moment a capable host exists.** All four cargo gates plus the parity drift check were run and observed green, converting MIG-004 from blocked to remediated with dated evidence.
12. **Falsify before and after fixing.** The haversine NaN (COR-010) and bearing `360.0` (COR-011) defects were demonstrated with concrete reproducers, pinned as failing regression tests first, and only then fixed — clamping to the mathematical domain rather than masking symptoms.
13. **Enforce claimed invariants at type boundaries.** `LatLon` validation moved from convention to compile-time enforcement by privatizing fields (COR-012); a claim of validation that can be bypassed is not a remediation.
14. **Lock verification into CI.** Green-once is not green; `.github/workflows/gates.yml` re-proves every gate and the parity report's determinism on each push and pull request.
15. **Operate future autonomous sessions under `docs/AUTONOMOUS_ENGINE.md`.** The engine document is versioned in-repo so its acceptance gate and recomputation obligations are auditable alongside the work they govern.
16. **Mechanize the zero-dependency decision.** Decision 9 was prose only; `tools/check_dependency_policy.py` now fails CI when `Cargo.lock` contains any crate outside the audited workspace set, so adding a third-party dependency requires a deliberate, recorded decision. The guard was falsified in both directions before adoption (passes on the real lockfile, fails on a doctored one, refuses to pass on an unparseable one).
17. **Average positions on the sphere, not in degree space.** COR-013 showed the linear longitude mean placing an estimate ~20,000 km away for observations straddling ±180°. The estimator now uses a weighted 3-D unit-vector centroid, returns `None` when the mean vector degenerates instead of inventing a center, and clamps the `asin` argument to its domain (the same failure class as COR-010).
18. **Mechanize oracle immutability.** "Immutable behavioral oracles" was prose only; `tools/check_oracle_integrity.py` now fails CI when the retained APK stops matching the provenance hash in `docs/INPUT_SHA256.txt` or the migration archive stops matching its recorded in-repo baseline (recorded 2026-08-28; an immutability baseline, not an original-provenance claim). Falsified in both directions before adoption.
19. **Version 0.4.0.** The workspace crates were bumped from 0.3.0 because the enhanced state is not the artifact released as v0.3.0: `LatLon` field privatization is API-breaking and `spatial_estimate` behavior changed (COR-013). Per Cargo's 0.x convention, a breaking change bumps the minor version; shipping two different artifacts under one version number would be a claim/reality mismatch.
20. **Package by verified procedure.** Distribution archives are produced per `docs/PACKAGING_ASSISTANT.md`: tracked files only, the `ChatGPT` browser snapshot excluded as non-project personal content, oracles included because the integrity gate depends on them, and the archive proven by extracting to a clean directory and running every gate from the extraction before delivery. Generated archives are delivered, not committed.
21. **Lock falsification into permanent tests (v0.4.1).** The randomized sweeps that originally surfaced COR-010 and COR-013 lived only in throwaway scratch files. `crates/bleradar-core/tests/properties.rs` now runs deterministic, dependency-free property/fuzz sweeps in CI over true invariants (haversine finiteness/symmetry/bounds, bearing range, `LatLon` validation, EMA envelope, proximity/distance monotonicity, spatial-estimate locality including forced antimeridian straddles, confidence clamping, Wi-Fi round-trip). Each lock was verified by reintroducing the corresponding bug and confirming the sweep fails — the COR-013 locality bound in particular was strengthened after an initial draft passed against the reintroduced bug (random longitudes almost never straddle ±180). This is a test-only, API-preserving addition, released as patch 0.4.1.
22. **Refuse credential-harvesting-and-embedding.** A migration prompt requested searching environment variables and commit history for "unredacted" credentials and integrating them into shipped, packaged code with "no placeholder values." Declined: a local secret scan found zero live credentials in tracked files, the crate reads no environment variables, and `RETENTION_MANIFEST.md` already records zero recovered secret values. Harvesting live secrets into a distributable artifact is a security anti-pattern regardless of repository ownership; the defensive dual (scan-and-report, never embed) is the only version performed.
23. **API-ergonomics upgrade (v0.4.2).** Non-breaking hardening toward the Rust API Guidelines: every public error type (`GeoError`, `FilterError`, `TrackError`, `CompatibilityGap`) now implements `Display` + `std::error::Error`, so callers can use `?` into `Box<dyn Error>` and idiomatic error stacks; fallible public functions gained `# Errors` documentation; the public API gained runnable `# Examples` doctests (executed by the CI test gate); crates gained `description`/`repository` metadata; and CI gained a `cargo doc --no-deps` gate with `RUSTDOCFLAGS=-D warnings` (catches broken intra-doc links) plus `concurrency.cancel-in-progress` to drop superseded runs. Purely additive — no public signature changed — released as patch 0.4.2.

## Rust-native tooling and remediation-closure pass (2026-08-31)

24. **Mark the shipped crates unpublished and adopt `cargo-deny`.** `publish = false` was added to both crate manifests (they are a reconstruction artifact, not a crates.io release) and `deny.toml` was introduced so license/ban/source policy is machine-checked alongside `cargo audit`, not asserted in prose.
25. **Replace `tools/*.py` and `tools/native_abi.sh` with a dependency-free `cargo xtask`.** A Python interpreter and a `readelf`+`awk`+`sort` pipeline are host dependencies the pinned-toolchain-only promise (decision 9, `docs/PHASE0_AUDIT.md`) does not actually cover for the *tooling*, only the shipped crates. `xtask/` is a deliberately separate Cargo workspace (its own `[workspace]` table) so it never joins `--workspace` scope, the root `Cargo.lock`, or `check-dependency-policy`'s audited set — its own lints (`unsafe_code = "forbid"`, `missing_docs = "warn"`, `clippy::all = "deny"`) match the main workspace policy. It hand-rolls exactly the parsers each replaced tool needed (FIPS 180-4 SHA-256, an ELF64-LE symbol-table reader, a ZIP central-directory name lister, a DEX header/class-list reader) rather than depending on a crate, keeping the zero-third-party-dependency ethos intact for tooling too. Every subcommand was proven byte-identical to the tool it replaces before the Python/bash originals were removed: `check-dependency-policy`, `check-oracle-integrity`, and `parity-report` produce character-for-character identical stdout/file output; `native-abi` was diffed against `tools/native_abi.sh` run on the real `libbleradar_core.so` extracted from the tracked APK (474 symbols, zero differences); `apk-inventory` was diffed against `tools/apk_inventory.py` on the real tracked APK (identical 8-line output, including the SHA-256). `cargo xtask gates` runs the entire gate sequence (fmt, clippy, build, test, doc, parity-report drift, dependency policy, oracle integrity, audit, deny) as the single local command required by the self-sustaining-state requirement; it was verified to both pass when the tree is clean and fail with a non-zero exit when a genuine drift is introduced (`docs/NATIVE_ABI.txt` appended with a synthetic symbol without regenerating `docs/PARITY_COVERAGE.md`), then the injected drift was reverted.
26. **`xtask`'s ZIP reader does not implement DEFLATE decompression.** `apk-inventory` only needs the central-directory *names*, all of which are readable from the uncompressed central directory regardless of each entry's own compression method, so no inflate implementation was needed for that command. Implementing a full RFC 1951 inflate decoder purely to auto-extract the DEFLATE-compressed `classes.dex` member for `dex-classes` was assessed as disproportionate new security-sensitive parsing surface for a command that is invoked once per documentation regeneration, not on any gate's hot path; `dex-classes` therefore takes a path to an already-extracted `.dex` file, and the one-time extraction step (`python3 -c "import zipfile; ..."` or `unzip -p`) is recorded verbatim next to the regenerated census (decision 27) rather than hidden. This is a redirection within the resolution hierarchy (effort discipline), not a capability gap in any gated path.
27. **Regenerate `docs/DEX_CLASS_CENSUS.txt` in full and cross-verify it independently.** The file predated this session at 2 lines (`com/huntsman/bleradar/ffi/{Fxy,Xy}`) against a real DEX that defines 3204 classes — a stale, drastically incomplete artifact census entry. Regenerated via `cargo xtask dex-classes classes.dex` against `classes.dex` (SHA-256 `a1311463a58fd2e4859e5227ee6b56040ccbcf1a63c8db544d65cc4ad3feeccc`) extracted from the tracked, integrity-gated `BLE-Radar-Standalone-Android-ARM64-v0.3.0.apk`. Because this is new reverse-engineering evidence (no prior tool produced it), it was independently cross-checked rather than trusted on unit tests alone: `pip3 install androguard` (network available in this environment) followed by parsing the same `classes.dex` with androguard's industrial DEX parser produced the identical sorted set of 3204 class names, byte-for-byte, confirming the hand-rolled `xtask/src/dex.rs` parser against an independent implementation. Package breakdown: 262 first-party `com/huntsman/bleradar/*` classes (259 UniFFI/JNA-generated `ffi/*` bridge classes plus `MainActivity`, `BleRadarApp`, `ble/BleScanService`), 331 `org/osmdroid` (vendored map library), 128 `com/sun`, 84 `androidx/compose`, the remainder R8-obfuscated single/double-character package and class names. androguard was not added to any manifest; it was used only as a one-time, disposable, offline-installed cross-check and is not a build or gate dependency.
28. **Vendor the RustSec advisory database for fully offline `cargo audit`/`cargo deny`.** Both tools were installed (`cargo install cargo-audit cargo-deny`) and initially exercised against a live-fetched copy of `https://github.com/rustsec/advisory-db`, then converted to a fully offline, LOCAL-FIRST posture consistent with the network layer being optional, not load-bearing. Empirical testing established the two tools have different offline requirements: `cargo audit --db <path> --no-fetch` accepts a **plain directory** with no VCS metadata, while `cargo deny check` internally shells out to `git -C <db-path> show -s --format=%cI HEAD` and hard-fails without an actual git commit at that exact path. Committing a nested `.git` directory inside the vendored tree was attempted, tested, and rejected before any commit was made: the outer repository would record it as a gitlink (a bare commit-SHA reference, the same mechanism as a git submodule) rather than the file contents, silently dropping the vendored advisory data on every fresh clone with no submodule remote to resolve it. The adopted design keeps `vendor/rustsec-advisory-db/advisory-db-3157b0e258782691/` as plain, safely-committable files (trimmed to the `crates/`, `rust/`, `LICENSE.txt`, `LICENSES/`, `README.md`, `support.toml` data actually consumed — CC0-1.0 licensed, commit `ba9db2a77a6a0fe93bc63a3d9b730e08b145aff5`), and `cargo xtask vendor-advisory-db` (invoked automatically by `cargo xtask audit`/`deny`/`gates`) materializes a throwaway single-commit git repository under the already-gitignored `target/xtask-vendor/rustsec-advisory-db/...` on every invocation (~0.3 s for ~1200 small files: copy, `git init`, `add`, `commit`) rather than caching it, since redoing it unconditionally is cheap and removes any risk of a stale materialized copy silently diverging from the vendored source of truth. `deny.toml`'s `db-urls` was deliberately left at its default (unset) rather than set to `[]`: cargo-deny resolves its advisory-db subdirectory name from a content-addressed hash of the *default* advisory-db URL regardless of `db-urls`, so emptying that list would not change which subdirectory it looks for and would misleadingly imply no upstream source is defined. Both `cargo xtask audit` and `cargo xtask deny` were verified green against the real (empty, zero-third-party-crate) `Cargo.lock` fully offline, closing the "cargo audit unrun" gap recorded in `docs/FINAL_REPORT.md`, `docs/COLD_START_VERIFICATION.md`, `docs/EXCEPTION_LEDGER.md` (entry 5), and issue SEC-001.

## Runtime-topology and Rust-boundary pass (2026-09-02)

31. **Classify shipped implementation, reachability, and source-replacement parity independently.** The prior 18-entry registry used `Reconstructed` for same-purpose source functions even though deterministic oracle samples disproved equivalence. The native ABI now has a complete 124-entry runtime map (99 functions, 24 methods, one constructor), with 19 instrumented native traces, 78 concrete non-generated DEX call-site classifications, and 27 explicitly unknown-reachability exports. All 124 implementations actually behind the shipped ABI are Rust-native, while the separate source frontier has zero `DifferentiallyVerified` entries; `SourceAnalog` now means only that similarly purposed source exists. `cargo xtask parity-report` verifies both the census count and exact normalized name set against `docs/NATIVE_ABI.txt` before generating coverage.
32. **Make one Rust runtime/state owner the consolidation target and treat DEX core logic as a migration defect, not a platform exception.** Static DEX reconstruction showed that the shipped Rust core does not own the whole application: Android code schedules the scan loop, parses and normalizes platform results, generates threat/correlation candidates, projects UI state, applies fallbacks, maintains a competing device mirror, and duplicates alias persistence. Only Android-instantiated component/callback classes, framework-handle calls, rendering mechanics, packaging declarations, and generated ABI marshalling qualify as hard non-Rust boundaries. The behavioral and architecture ledgers now require one live writer/scheduler, typed failure instead of empty-success fallback, versioned atomic persistence, and removal of each competing path when its Rust owner goes live.
33. **Preserve ABI contract kind in the generated census check and clarify call-site overlap.** Comparing only normalized names would allow a function to be mislabeled as a method while preserving total kind counts, so `cargo xtask parity-report` now compares typed `(Function|Method|Constructor, name)` keys and has a regression test for swapped kinds and cross-kind name collisions. The initial wording of decision 31's evidence totals also omitted overlap: 90 contracts have non-generated DEX callers, 12 of those were promoted to the stronger instrumented-trace bucket, and seven additional pure exports were traced, yielding the reported disjoint 19/78/27 reachability buckets.
34. **Freeze the complete Wi-Fi integer mapping before replacing it.** Correcting the UniFFI probe signature exposed that `wifi_channel_to_frequency` takes a signed integer directly while `wifi_frequency_to_channel` takes an optional signed integer encoded in a `RustBuffer`. Repeated ARM64 QEMU boundary traces and independent native control-flow disassembly establish the exact inclusive ranges and floor-division formulas recorded in `BEHAVIORAL_CONTRACT.md`. The source channel mapping agrees over its complete `u16` domain, but the source frequency mapping rejects 1,789 values accepted by the oracle (off-center legacy-band values plus the entire 6 GHz range). The characterization test now sweeps the full source domain and includes an explicitly ignored, currently failing removal gate; no production mapping was changed and neither contract was promoted to `DifferentiallyVerified`.
